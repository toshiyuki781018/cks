# 問題01：Control Planeコンポーネントのセキュリティ設定を是正する

## 対象領域

Cluster Setup / System Hardening

## 教材種別

Drill（試験対策問題）

目安時間：10〜15分

# 背景

あなたは、`kubeadm` を使用して構築されたKubernetesクラスターのセキュリティ確認を担当しています。  
クラスターに対してCIS Benchmarkを基準としたセキュリティチェックを実施したところ、  
kubeletおよびetcdについて、アクセス制御に関する複数の問題が検出されました。

現在の設定では、必要な認証・認可を経由せずにアクセスできる可能性があるため、  
クラスターのセキュリティ要件を満たすように設定を是正してください。

# 初期観測情報

セキュリティチェックの結果、次の状態が確認されています。

### kubelet

* 認証情報を持たないクライアントからのアクセスを受け付ける設定になっています。  
* APIへの要求を無条件で許可できる認可方式が使用されています。

### etcd

* クライアントからの接続時に、信頼されたクライアント証明書を必須とする設定が有効になっていません。

# 要件

以下のセキュリティ要件をすべて満たしてください。

1. kubeletへアクセスするクライアントには認証を要求し、匿名によるアクセスを許可しないこと。
2. kubeletへの要求について、すべてのアクセスを無条件に許可する認可方式を使用しないこと。
3. etcdへ接続するクライアントには、信頼されたCAによって検証可能なクライアント証明書を要求すること。
4. 設定変更後もControl Planeが正常に動作すること。

# 設定情報

| 項目            | 設定内容                                  |
| ------------- | ------------------------------------- |
| クラスター構築方式     | `kubeadm`                             |
| kubelet設定ファイル | `/var/lib/kubelet/config.yaml`        |
| etcdマニフェスト    | `/etc/kubernetes/manifests/etcd.yaml` |
| etcd証明書ディレクトリ | `/etc/kubernetes/pki/etcd/`           |

# 制約

* kubeletおよびetcdそのものを削除・再構築してはいけません。
* 既存クラスターで使用されている証明書および秘密鍵を利用してください。
* セキュリティ要件を満たすために必要な範囲のみ設定を変更してください。
* 設定変更によって既存のControl Plane通信を破壊しないようにしてください。

# 完了条件

以下をすべて満たした場合、作業完了とします。

* kubeletへの匿名アクセスが許可されていない。
* kubeletがすべての要求を無条件に許可する認可方式を使用していない。
* etcdがクライアント証明書による認証を要求している。
* 必要な設定変更が実際のコンポーネントへ反映されている。
* Kubernetesクラスターが設定変更後も正常に動作している。

# 作業後の確認項目

設定変更後、次の内容を確認してください。

* kubeletの設定がセキュリティ要件を満たしていること。
* kubeletが変更後の設定で正常に動作していること。
* etcdのクライアント認証設定が有効になっていること。
* etcdが正常に稼働していること。
* Control PlaneのPodが正常な状態であること。
* `kubectl`を使用してクラスターの状態を正常に取得できること。

# 注意事項

設定項目の名前だけを探すのではなく、

**「誰からのアクセスを許可するのか」**  
**「アクセスを許可するかどうかを、どこで判断するのか」**  
**「etcdへ接続するクライアントを、どのように信頼するのか」**

という観点から、変更すべき設定を判断してください。

また、認証を強化する場合は、認証を有効にする設定だけではなく、  
認証を成立させるために必要な証明書・秘密鍵・CAの関係にも注意してください。
