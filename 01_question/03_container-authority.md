# 問題03：コンテナ実行権限を最小化する

## 対象領域

System Hardening / Minimize Microservice Vulnerabilities

## 教材種別

Drill（試験対策問題）

目安時間：10〜15分

# 背景

社内向けWebアプリケーションをコンテナ化し、Kubernetes上で稼働させる準備を進めています。

セキュリティレビューを実施したところ、コンテナイメージの実行ユーザーと、  
Kubernetes上でコンテナへ与えられる権限について、過剰な権限が残っていることが確認されました。

コンテナが侵害された場合でも、影響範囲をできるだけ小さくするため、  
イメージ側とKubernetes側の両方を確認し、既存設定をセキュリティ要件に合う状態へ修正してください。

# 初期観測情報

対象となるファイルは次の2つです。

```text
/cks/docker/Dockerfile
/cks/docker/deployment.yaml
```

セキュリティレビューでは、次の問題が確認されています。

### コンテナイメージ

* アプリケーションのメインプロセスが特権ユーザーで実行される構成になっています。

### Kubernetes実行環境

* コンテナ実行時に不要な権限を保持できる設定になっています。
* コンテナのルートファイルシステムへ書き込み可能な状態です。
* コンテナが過剰なLinux Capabilityを保持できる状態です。

# 要件

以下のセキュリティ要件をすべて満たしてください。

1. コンテナのメインプロセスをrootユーザーとして実行しないこと。
2. Kubernetes上でも、コンテナを指定された非特権ユーザーとして実行すること。
3. コンテナのルートファイルシステムへ書き込みできないようにすること。
4. コンテナを特権コンテナとして実行しないこと。
5. 不要なLinux Capabilityを保持させないこと。
6. Webサーバーの動作に必要なCapabilityだけは利用できる状態を維持すること。

# 設定情報

| 項目               | 設定内容                          |
| ---------------- | ----------------------------- |
| Dockerfile       | `/cks/docker/Dockerfile`      |
| Deploymentマニフェスト | `/cks/docker/deployment.yaml` |
| 使用する非特権ユーザー      | `anyone`                      |
| 使用するUID          | `65535`                       |

# 制約

* Dockerfileに新しいディレクティブを追加してはいけません。
* Dockerfileから既存のディレクティブを削除してはいけません。
* Deploymentマニフェストに新しいフィールドを追加してはいけません。
* Deploymentマニフェストから既存のフィールドを削除してはいけません。
* 既存の設定値のみを変更してください。
* 非特権ユーザーで実行する場合は、UID `65535`を使用してください。
* アプリケーションがWebサーバーとして必要とする最低限の権限は維持してください。

# 完了条件

以下をすべて満たした場合、作業完了とします。

* Dockerfile上で、コンテナがrootユーザーとして実行されない。
* Kubernetes上でも、コンテナがUID `65535`で実行される。
* コンテナのルートファイルシステムが書き込み不可になっている。
* コンテナが特権モードで実行されない。
* 不要なLinux Capabilityが削除されている。
* Webサーバーに必要なCapabilityのみが利用できる。
* 既存の設定項目を追加・削除していない。

# 作業後の確認項目

修正後、次の内容を確認してください。

* Dockerfileで指定されている実行ユーザーが非特権ユーザーになっていること。
* Deploymentで指定されている実行UIDが`65535`になっていること。
* コンテナのルートファイルシステムが書き込み不可になっていること。
* 特権コンテナとして実行されない設定になっていること。
* 不要なLinux Capabilityが削除されていること。
* Webサーバーが必要とするCapabilityが維持されていること。
* DockerfileおよびDeploymentで、設定項目そのものを追加・削除していないこと。

# 注意事項

今回の問題では、

**「Kubernetesの設定だけを直せばよい」**

とは限りません。

コンテナがどの権限で動作するかは、

```text
コンテナイメージ
    ↓
Dockerfile
    ↓
実行ユーザー

Kubernetes
    ↓
Deployment
    ↓
コンテナ実行時の権限
```

という複数のレイヤーで決まります。

そのため、

```text
コンテナが侵害される可能性
        ↓
侵害後にどの権限を利用できるのか
        ↓
どのユーザーで動作するのか
        ↓
どこへ書き込めるのか
        ↓
どのCapabilityを利用できるのか
```

という観点から、DockerfileとDeploymentの両方を確認してください。

また、すべての権限を単純に削除するのではなく、  
**アプリケーションの動作に本当に必要な権限だけを残す**  
という最小権限の考え方を意識してください。
