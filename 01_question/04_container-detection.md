# 問題03：不審なファイルアクセスを検出する

## 対象領域

Monitoring, Logging and Runtime Security / Falco / Runtime Detection

## 教材種別

Drill（試験対策問題）

目安時間：10〜15分

# 背景

Kubernetesクラスターでは、コンテナの実行時に発生する不審な操作を検出するため、Falcoが導入されています。

セキュリティチームから、実行中のコンテナによる特定のデバイスファイルへの  
アクセスを検出できるようにしてほしいという依頼がありました。

このファイルは通常のアプリケーションではアクセスする必要がなく、コンテナからアクセスされた場合には、  
侵害や不適切な権限利用の可能性を調査する必要があります。

既存のFalcoルールを参考にしながら、指定されたアクセスを検出するためのカスタムルールを作成し、  
Falcoへ反映してください。

# 初期観測情報

対象NodeにはFalcoがインストールされています。

Falcoの既存ルールおよびカスタムルールは、次のファイルから確認できます。

```text
/etc/falco/falco_rules.yaml
/etc/falco/falco_rules.local.yaml
```

今回検出対象とするファイルは次のとおりです。

```text
/dev/mem
```

検出後の調査で対象コンテナを特定できるようにする必要があります。

# 要件

以下の要件をすべて満たすFalcoのカスタムルールを作成してください。

1. `/dev/mem`へのファイルアクセスを検出すること。
2. 検出対象となるファイルをFalcoのListとして定義すること。
3. ファイルアクセスを判定するため、アクセスされたファイル名を条件として使用すること。
4. 検出時の出力には、アクセスが発生したことが分かるメッセージを含めること。
5. 検出時の出力には、対象コンテナを後から特定できる情報としてContainer IDを含めること。
6. 検出イベントのPriorityは`NOTICE`とすること。
7. 作成したルールには、ファイルアクセスに関するルールであることを識別できるTagを設定すること。
8. カスタムルールは、既存のFalcoルールを直接変更せず、ローカルルール用のファイルへ追加すること。
9. 作成したルールをFalcoが読み込める状態にすること。

# 設定情報

| 項目                    | 設定内容                                |
| --------------------- | ----------------------------------- |
| Runtime Security Tool | Falco                               |
| 検出対象                  | `/dev/mem`                          |
| カスタムルールファイル           | `/etc/falco/falco_rules.local.yaml` |
| Priority              | `NOTICE`                            |
| 出力に必要な情報              | Container ID                        |
| Tag                   | ファイルアクセスを識別できるもの                    |

# 制約

* `/etc/falco/falco_rules.yaml`の既存ルールを直接変更してはいけません。
* Falcoをアンインストールまたは再インストールしてはいけません。
* Kubernetes Workloadの設定を変更してはいけません。
* 検出対象を`/dev/mem`以外へ変更してはいけません。
* 実際に`/dev/mem`へのアクセスを発生させる必要はありません。
* Container IDからPodやDeploymentを特定する作業は、この問題の対象外です。
* Workloadを停止・削除する必要はありません。

# 完了条件

以下をすべて満たした場合、作業完了とします。

* `/etc/falco/falco_rules.local.yaml`にカスタムルールが存在する。
* `/dev/mem`が検出対象として定義されている。
* `/dev/mem`へのファイルアクセスを判定する条件が設定されている。
* 検出時の出力にContainer IDが含まれている。
* Priorityが`NOTICE`になっている。
* ファイルアクセスを識別できるTagが設定されている。
* Falcoが作成したルールを読み込める状態になっている。

# 作業後の確認項目

設定後、次の内容を確認してください。

* カスタムルールファイルに作成したRuleが存在すること。
* 検出対象のListに`/dev/mem`が含まれていること。
* RuleのConditionがファイル名を判定する構成になっていること。
* OutputにContainer IDが含まれていること。
* Priorityが`NOTICE`であること。
* Tagが設定されていること。
* Falcoがカスタムルールを読み込めること。

# 注意事項

この問題では、実際に不正アクセスを発生させてAlertを確認することは目的としていません。

考えるべきなのは、

```text
何を異常とするか
        ↓
どのRuntime Eventを観測するか
        ↓
何を条件として判定するか
        ↓
検出後の調査に何の情報が必要か
        ↓
Falco Ruleへ落とし込む
```

という流れです。

今回の場合、

```text
異常行動
 ↓
/dev/memへのアクセス

観測対象
 ↓
アクセスされたファイル

判定
 ↓
ファイル名が/dev/memか

検出後
 ↓
どのコンテナだったか調査したい

必要な出力
 ↓
Container ID
```

と整理できます。

Falcoの設定項目を暗記するのではなく、  
**「検出したい行動を、観測条件と調査に必要な情報へ分解してRuleへ変換する」**  
という観点から設定してください。
